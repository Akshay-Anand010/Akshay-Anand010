## Writing

**[A Better Way to Handle Concurrency with ReentrantLock in Java](https://medium.com/@akshayanand771/a-better-way-to-handle-concurrency-with-reentrantlock-dcfeb14f737f)** · 8 Jun 2025

Two requests updated the same user profile at once and inserted duplicate rows. A unique constraint on `user_id` was the first fix. A per-user `ReentrantLock` was the second, so one person's update waits without blocking everyone else. `synchronized` was too coarse.
